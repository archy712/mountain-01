당신은 1인 개발자 및 소규모 프로젝트를 위한 실용적인 PRD 작성 전문가입니다.
대기업식 복잡한 절차나 불필요한 형식은 배제하고, "바로 개발에 착수할 수 있는"
구체적이고 실행 가능한 PRD를 작성하세요.

# 프로젝트 개요

**제품명:** (적절한 서비스명을 제안할 것)
**한 줄 설명:** 등산 코스 정보와 실시간 날씨를 연동해 제공하는 아웃도어 모바일 웹 애플리케이션
**타깃 사용자:** 등산을 계획하는 일반 등산객 (모바일 환경 우선)
**핵심 가치:** 산에 가기 전, "지금 이 산에 가도 되는지"를 한 화면에서 판단하게 해준다.

# 기술 스택 (확정)

- **프레임워크:** Next.js 16 (App Router)
- **인증/DB:** Supabase (@supabase/ssr, 쿠키 기반 세션)
- **스타일링:** Tailwind CSS v4 + shadcn/ui (new-york)
- **지도:** 카카오맵 (Kakao Maps SDK) — 3단계에서 도입
- **배포 형태:** 모바일 웹 우선 + PWA (3단계)
- **외부 데이터 연동(예상):**
  - 기상청 단기예보 / 미세먼지·자외선 API (또는 대체 공공 API)
  - 국립공원공단 탐방로 개방정보 (또는 대체 데이터 소스)
  * 정확한 API가 불확실한 경우, "확정 필요 항목"으로 표시하고 후보를 제안할 것

# 개발 단계 (이 순서와 범위를 반드시 반영할 것)

## 1단계 — MVP: 날씨 + 탐방로 조회
- 산 이름 검색 → 오늘 날씨 + 탐방로 개방 여부 표시
- 최소 기능으로 "검색 → 결과 확인" 흐름이 완결되어야 함

## 2단계 — 컨디션 점수 + 장비 추천
- 미세먼지·자외선·날씨를 통합한 "등산 컨디션 점수" 알고리즘
- 날씨 조건 기반 장비 추천 로직 (예: 강수 → 방수자켓, 저온 → 방한장비)

## 3단계 — 지도 시각화 + 모바일 최적화
- 카카오맵 위에 등산로 오버레이 표시
- PWA 적용 + "홈 화면에 추가" 지원

# 작성 지침

1. **각 단계(1~3)를 독립된 섹션으로 구성**하고, 단계별로 다음을 포함할 것:
   - 사용자 스토리 (누가 / 무엇을 / 왜)
   - 핵심 기능 목록 (구현 우선순위 표시: Must / Should / Could)
   - 화면 구성 (주요 페이지/컴포넌트 단위로, 라우트 경로 포함)
   - 데이터 요구사항 (Supabase 테이블 스키마 초안, 외부 API 응답 필드)
   - 완료 기준(Acceptance Criteria) — 체크리스트 형태
2. **2단계의 컨디션 점수 알고리즘**은 입력 변수, 가중치 예시, 점수 구간(예: 0~100, 등급)을
   구체적인 표로 제시할 것. (완성된 정답이 아니라 개발 시작점이 되는 초안)
3. **비기능 요구사항**을 별도 섹션으로: 성능(모바일 로딩), 접근성, 에러/로딩 상태 처리,
   외부 API 실패 시 폴백 전략.
4. **데이터 모델**은 이 저장소의 Supabase 컨벤션을 따를 것:
   - RLS(Row Level Security) 정책 필요 여부 명시
   - `lib/supabase/database.types.ts` 재생성이 필요한 테이블 표시
5. **명확히 결정되지 않은 항목**은 임의로 확정하지 말고 "🔶 확정 필요" 라벨과 함께
   선택지·추천안을 제시할 것 (특히 외부 API 선정, 데이터 갱신 주기, 캐싱 전략).
6. **범위 밖(Out of Scope)** 항목을 명시하여 스코프 크리프를 방지할 것.
   (예: 회원 커뮤니티, 예약, 결제, 실시간 위치 추적 등)
7. 문체는 한국어, 간결한 개조식. 개발자가 바로 티켓으로 쪼갤 수 있는 수준의 구체성을 유지.

# 출력 형식

- Markdown 문서 하나로 작성.
- 최상단에 문서 제목, 버전, 작성일, 요약(3~4줄)을 배치.
- 목차(TOC) 포함.
- 아래 구조를 따를 것:

  1. 개요 (제품 정의 / 타깃 / 핵심 가치)
  2. 목표 및 성공 지표 (측정 가능한 KPI 초안)
  3. 사용자 페르소나 (1~2명)
  4. 단계별 요구사항
     - 4.1 1단계 MVP
     - 4.2 2단계 컨디션 점수 + 장비 추천
     - 4.3 3단계 지도 + PWA
  5. 데이터 모델 (Supabase 스키마 초안)
  6. 외부 API 연동 명세
  7. 비기능 요구사항
  8. 범위 밖(Out of Scope)
  9. 확정 필요 항목 정리 (🔶 목록)
  10. 향후 확장 아이디어

## 사용 방법

1. 위 코드블록 안의 프롬프트 전체를 복사합니다.
2. Claude Code 프롬프트 창에 붙여넣거나, `prd-generator` 서브에이전트에게 전달합니다.
3. 생성된 결과는 `docs/PRD.md` 로 저장됩니다.
4. 🔶 확정 필요 항목을 검토·결정한 뒤, 해당 부분을 채워 PRD를 확정합니다.

## 커스터마이징 포인트

- **제품명/타깃**을 이미 정했다면 프롬프트의 "프로젝트 개요"에 직접 기입하세요.
- **외부 API가 확정**되었다면 "외부 데이터 연동" 항목을 실제 API로 교체하세요.
- 단계를 더 잘게 나누고 싶다면, 각 단계에 스프린트/마일스톤 단위를 추가로 요청하세요.
