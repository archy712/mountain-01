## 🔶#6 — 자외선 API

**결정: 기상청 생활기상지수 조회서비스 V5의 자외선지수 조회(`getUVIdxV5`)로 확정.** (※ 엔드포인트 버전 **V5** — 초안 3.0 → 4.0 → **V5로 최종 정정**)

- **확정 엔드포인트:** `GET https://apis.data.go.kr/1360000/LivingWthrIdxServiceV5/getUVIdxV5`
  - 파라미터: `serviceKey`(Encoding 그대로), `areaNo`(행정구역코드 10자리), `time`(YYYYMMDDHH, **06·18시 발표**), `dataType=JSON`, `numOfRows`, `pageNo`
  - `areaNo`는 서비스 상세 페이지 첨부 "지역코드" 파일에서 확정
- 공신력 있는 무료 소스이며, 지역코드(행정구역) 매핑 방식으로 조회.
- **현재 상태(2026-08-08 재테스트):** ✅ **라이브 정상**(HTTP 200, `resultCode=00 NORMAL_SERVICE`, totalCount=1). `KMA_LIVING_INDEX_KEY`(3키 동일 값)로 정상 조회.
  - **직전 코드30 원인 규명:** 이전 실패는 키/게이트웨이 문제가 아니라 **엔드포인트 버전 오류**(`LivingWthrIdxServiceV4/getUVIdxV4`)였음. V4 경로는 이 계정 키에 미등록이라 코드30 반환. **V5 경로로 교체하니 즉시 정상.**
  - 응답 스키마: `items.item[0]`에 `code`(지역), `areaNo`, `date`(YYYYMMDDHH 발표시각), **`h0`~`h75`(발표시각 기준 3시간 간격 UV 지수 예보값)**. 값 없는 시간대는 빈 문자열. → Task 022에서 `h0`(현재 시각 인근)~단기 구간 파싱.
- 에어코리아·기상청 단기예보도 라이브 **정상 확인됨** (2026-08-08 재테스트 통과).
- **영향 Task:** Task 022(자외선 연동 — 지역코드 매핑)

## 100대명산 목록·좌표 (Task 036)

**결정: 산림청 선정 100대명산(2002)을 산 마스터 콘텐츠로 편입한다. 목록/고도/지역은 공개 사실 데이터, 좌표는 기존 시드와 동일한 "대표 정상 근사값" 기준을 적용한다.**

- **목록·고도·지역 출처:** 위키백과 "대한민국 100대 명산 목록"(산림청 2002년 선정 공표 목록). 100대명산 "선정 목록" 자체는 저작권 대상이 아닌 공개 사실 정보이며, 산 이름·소재지(도)·해발고도는 공표 자료 기준으로 표기한다.
- **좌표(lat/lng):** 대표 정상 근사값을 사용한다(기존 `gen-mountains.mjs`와 동일 기준). 컨디션·날씨는 기상청 **5km 격자**로 조회되므로 정상 근사 좌표로 충분하다.
- **정밀 좌표 정식 소스(향후):** 한국등산·트레킹지원센터 **100대명산 목록정보 서비스**(공공데이터포털 `15125127`, 위도·경도·해발고도·주소 제공). 현재 이 계정에 미구독(활용신청 필요)이라 좌표 정밀화는 후속 과제로 남긴다.
- **동명 산 처리:** 100대명산에는 동명 산이 존재(백운산 3곳·지리산 2곳·남산은 경주). 검색은 지역명 병기로 구분(결정 002 #2)하며, 기존 서울 남산/북악산/인왕산/수락산/청계산은 100대명산이 아니므로 `is_top100=false`로 유지한다.
- **영향 Task:** Task 036(100대명산 목록 화면)

## 산불위험예보 (Task 043)

**결정: 산림청 국립산림과학원 "산불위험예보정보" 오픈API를 신규 소스로 채택한다. 지역·날짜별 산불위험지수(1~100)를 조회해 상세 화면 배지 + 컨디션 점수 감점 요인으로 편입한다.** (조사일 2026-08-10)

- **출처:** 산림청 국립산림과학원_산불위험예보정보 — 공공데이터포털 `15084817` (`https://www.data.go.kr/data/15084817/openapi.do`). 지형·임상·기상 빅데이터로 전국 시도/시군구/읍면동 시간별 위험지수를 산출, 3일(72시간) 예보를 3시간 간격 제공. **라이브 정상 확인(2026-08-10)**.
- **베이스 URL(확정):** `https://apis.data.go.kr/1400377/forestPointV2` (HTTPS, **V2**). 인증키는 `.env.local` `FOREST_FIRE_SERVICE_KEY`(Encoding 형태 → 코드에서 `decodeURIComponent` 1회, 날씨·자외선과 동일 규칙).
  - **오퍼레이션(확정, 각 1,000회/일):** 전국 `/forestPointListGeongugSearchV2`, **시도 `/forestPointListSidoSearchV2`(채택)**, 시군구 `/forestPointListSigunguSearchV2`.
- **요청 파라미터(확정):** `serviceKey`, `_type=json`, `pageNo`, `numOfRows`. **시도 오퍼레이션은 지역코드 파라미터 없이 전국 16개 시도를 한 번에 반환**(totalCount 16) → 산별 호출 불필요, 발표 슬롯 단위 1회 캐싱으로 충분.
- **응답 필드(확정):** `response.body.items.item[]` 각 원소에 `regioncode`(시도 코드)·`doname`(시도명)·**`meanavg`(평균지수=대표값 채택)**·`maxi`/`mini`·`std`·`d1~d4`(등급별 면적 분포%)·`analdate`("YYYY-MM-DD HH"). `resultCode`는 `00`=정상.
- **위험 등급(확정):** 지수 1~100 → **매우높음(86+) / 높음(66~85) / 다소높음(51~65) / 낮음(50 이하)** 4단계.
- **시도 코드 매핑(확정, 라이브 응답 기준):** 서울11·부산26·대구27·인천28·대전30·울산31·세종36·경기41·충북43·충남44·경북47·경남48·제주50·**강원51**(구42 아님)·**전북52**(구45 아님)·**광주+전남=12 "전남광주통합특별시"**(29·46 부재). 산 `region` 토큰(REGION_ORDER)→코드 매핑은 `forest-fire-core.ts` `SIDO_REGION_CODE`.
- **지역 매핑 방침(확정):** 산 마스터는 `region`(시도 단위) + 위경도만 보유하므로 **시도 단위 위험지수**를 채택(자외선 `areaNo` coarse 매핑과 동일 관례). 여러 시도에 걸친 산(예: "대전·충남")은 각 시도 지수 중 **최댓값**을 대표값으로(안전 우선). 시군구 정밀화(위경도 역지오코딩)는 후속 과제.
- **캐싱:** `fire-3h` 프로필(revalidate 3h, 발표주기 정렬), 캐시 키 `fire:sido:{yyyymmdd}:{slot}`(3시간 슬롯). `withStaleFallback` 로 stale 폴백 + `api_logs` 자동 계측(source `fire`, CHECK 제약 마이그레이션 추가).
- **점수 편입(구현됨):** `lib/condition/score.ts` `ScoreFactor` "fire" 추가, 등급별 감점(낮음 0 / 다소높음 −10 / 높음 −20 / 매우높음 −30), 소스 실패·미커버 시 `excludedVariables` 격리(부분 폴백), **`CALC_VERSION` v1→v2**. 감점표는 결정 003 에 동결.
- **입산통제 범위 정리:** 이 API 는 위험 "지수"이지 통제 목록이 아니다. 산불조심기간(봄 2~4월·가을 11~12월) **정적 입산통제는 이미 `seasonal-closure.ts` 계절통제로 반영**됨. 실시간 입산통제 연동은 **Task 044(실시간 탐방로 통제)** 영역과 겹치므로, Task 043 은 **산불위험지수 배지 + 점수 감점**에 집중하고 실시간 통제는 044 로 넘겼다.
- **영향 Task:** ✅ Task 043(산불위험지수 연동 — 배지 + 점수 감점)

Task 044 는 정적 2023 CSV 스냅샷(#4)의 한계인 **실시간 돌발 통제**(사고·낙석·기상·산불특보 등)를 국립공원공단 라이브 소스로 보완하는 것이 목표였다. 착수 1단계로 라이브 소스 실재·필드·키·접근성을 조사한 결과, **현재 개인 개발자가 합법·안정적으로 쓸 수 있는 실시간 소스가 없어 보류**한다.

- **실시간 통제 데이터는 존재하나 개인이 API 로 못 받는다.** 국립공원공단 공식 사이트 출입통제 상세 페이지(`https://www.knps.or.kr/front/portal/safe/acsCtrDtl.do`)에 공원사무소별 실시간 통제가 게시된다(관측 필드: **공원(사무소)·상황(정상/부분통제/전면통제)·통제사유·통제구간·통제기간·기준시간·첨부 PDF**, 예: 치악산 부분통제 — 구룡계곡길(세렴폭포~비로봉삼거리)). 별도 "국립공원 탐방알리미" 앱도 실시간 통제를 제공하나 이는 내부 시스템 소비자다.
- **경로 A(공식 OpenAPI) — 막힘:** data.go.kr 에 대응 실시간 통제/공지 오픈API 가 있으나(사용자 확인), **공공기관 전용 데이터로 개인 개발계정은 활용신청 불가**. 발급 자체가 차단됨.
- **경로 B1(웹 스크래핑) — 막힘:** knps.or.kr `robots.txt` 는 `Disallow: /` 로 전 경로를 막고 `/front/portal/visit` 만 허용한다. 통제 페이지 `/front/portal/safe/acsCtrDtl.do` 는 **명시적 크롤링 금지 대상**이라 스크래핑은 사이트 정책 위반. 채택하지 않는다.
- **정합성:** Phase 0(위 #4, 실행 액션 line "~~국립공원공단 탐방로 개방정보 API~~ → 불필요")의 판단(개인 접근 라이브 API 부재)이 재확인됨.

**결정(확정):** Task 044 **보류.** 실시간 돌발 통제는 현 시점 개인 접근 소스가 없으므로, **정적 CSV 스냅샷 + 계절판정(`seasonal-closure.ts`) 베이스라인을 유지**한다. 산불조심기간 통제 등 **예측 가능·기간 명시 통제는 이미 계절판정으로 결정적으로 반영**되므로 핵심 기능 공백은 제한적이다. 국립공원 외 산은 기존대로 "정보 없음" 폴백.
