# 산길날씨(SanGil) PRD

- **문서 버전:** v1.0
- **작성일:** 2026-08-08
- **상태:** 초안 (개발 착수용)

> **요약**
> 산길날씨는 산 이름 하나만 검색하면 오늘의 날씨와 탐방로 개방 여부를 한 화면에서 확인하고, 나아가 "등산 컨디션 점수"와 장비 추천, 지도 시각화까지 제공하는 모바일 웹 앱이다.
> "지금 이 산에 가도 되는지"를 출발 전 3초 안에 판단하게 하는 것이 핵심 가치다.
> 3단계 점진 개발(MVP 날씨/탐방로 → 컨디션 점수/장비 추천 → 지도/PWA)로 스코프를 통제한다.
> 기술 스택은 Next.js 16 + Supabase + Tailwind v4/shadcn(new-york) + 카카오맵(3단계)으로 확정한다.

## 1. 개요

### 제품 정의

- **제품명:** 산길날씨 (SanGil) — _영문 후보: SanGil / TrailCast_ 🔶
- **한 줄 설명:** 등산 코스 정보와 실시간 날씨를 연동해 제공하는 아웃도어 모바일 웹 앱
- **형태:** 모바일 웹 우선 (반응형), 3단계에서 PWA 적용

### 타깃 사용자

- 주말/휴일 등산을 계획하는 일반 등산객
- 스마트폰으로 출발 직전 또는 전날 밤에 정보를 확인하는 사용자

### 핵심 가치

- 산에 가기 전, "지금 이 산에 가도 되는지"를 **한 화면에서 즉시 판단**하게 해준다.
- 흩어진 정보(기상청, 탐방로 개방정보, 미세먼지)를 하나의 결론(=컨디션 점수)으로 압축한다.

## 3. 사용자 페르소나

### 페르소나 1 — "주말 산행 김대리" (주 사용자)

- 32세 직장인, 월 1～2회 근교 산행(북한산·관악산 등).
- 금요일 밤 침대에서 스마트폰으로 "내일 이 산 갈 만한가?"를 확인.
- 니즈: 빠른 판단. 상세 기상 데이터보다 "가라/말라" 결론을 원함.
- 불편: 기상청·국립공원 앱을 각각 열어 비교하는 게 번거로움.

### 페르소나 2 — "장비 챙기는 초보 이씨" (2단계 타깃)

- 27세, 등산 입문 6개월차. 무엇을 챙겨야 할지 모름.
- 니즈: 오늘 날씨에 맞는 장비 추천(방수·방한 등).
- 불편: 막상 산에 가면 준비물이 부족해 고생한 경험.

## 4. 단계별 요구사항

### 4.1 1단계 MVP — 날씨 + 탐방로 조회

#### 사용자 스토리

- (누가) 산행을 계획하는 등산객이 (무엇을) 산 이름을 검색해 오늘 날씨와 탐방로 개방 여부를 (왜) 출발 전 한 화면에서 빠르게 확인하고 싶다.

#### 핵심 기능 목록 (우선순위)

| 기능                | 설명                              | 우선순위 |
| ------------------- | --------------------------------- | -------- |
| 산 검색             | 산 이름 입력 → 자동완성/후보 목록 | **Must** |
| 오늘 날씨 표시      | 기온/강수확률/하늘상태/풍속       | **Must** |
| 탐방로 개방 여부    | 개방/통제/부분통제 상태 표시      | **Must** |
| 검색 결과 요약 카드 | 날씨+탐방로 한 화면 요약          | **Must** |
| 산 상세 페이지      | 위치·고도 등 기본 메타            | Should   |
| 최근 검색 기록      | 로컬 저장 최근 검색어             | Should   |
| 비로그인 이용       | 인증 없이 검색 가능               | **Must** |

> MVP는 **비로그인 전체 이용 가능**. 인증(Supabase)은 2단계 즐겨찾기부터 필수화.

#### 화면 구성 (라우트 포함)

| 화면                        | 라우트            | 구성 요소                                         |
| --------------------------- | ----------------- | ------------------------------------------------- |
| 홈/검색                     | `/`               | 검색 인풋, 자동완성, 최근 검색, 인기 산 목록      |
| 검색 결과                   | `/mountains/[id]` | 요약 카드(날씨+탐방로), 상세 섹션, 로딩/에러 상태 |
| 검색 결과(쿼리형 대체안) 🔶 | `/search?q=`      | 목록형 결과 → 상세 이동                           |

- 주요 컴포넌트: `MountainSearchInput`, `WeatherSummaryCard`, `TrailStatusBadge`, `MountainDetail`, `ResultSkeleton`, `ErrorFallback`.

#### 데이터 요구사항

- **Supabase 테이블:** `mountains` (산 마스터 데이터), `trails` (탐방로), `search_logs`(선택).
- **외부 API(읽기):**
  - 기상청 단기예보: `TMP`(기온), `POP`(강수확률), `SKY`(하늘상태), `PTY`(강수형태), `WSD`(풍속).
  - 탐방로 개방정보: 산/탐방로명, 개방상태(개방/통제/부분), 통제사유, 통제기간.
- 산 → 격자좌표(nx, ny) 매핑 필요(기상청 격자). `mountains.grid_nx/grid_ny` 사전 적재. 🔶

#### 완료 기준 (Acceptance Criteria)

- [ ] `/`에서 산 이름 검색 시 300ms 내 자동완성 후보가 노출된다.
- [ ] 산 선택 시 `/mountains/[id]`로 이동하고 오늘 날씨 요약이 표시된다.
- [ ] 탐방로 개방 상태가 개방/통제/부분통제 배지로 명확히 구분된다.
- [ ] 외부 API 실패 시 에러 폴백 UI가 노출되고 앱이 크래시하지 않는다.
- [ ] 로그인 없이 검색～결과 확인 전체 흐름이 완결된다.
- [ ] 모바일(360px 폭)에서 레이아웃 깨짐이 없다.

### 4.2 2단계 — 컨디션 점수 + 장비 추천

#### 사용자 스토리

- (누가) 산행 초보/일반 등산객이 (무엇을) 통합 컨디션 점수와 장비 추천을 (왜) 개별 수치를 해석하지 않고도 "가라/말라"와 "챙길 것"을 바로 알기 위해.

#### 핵심 기능 목록 (우선순위)

| 기능                 | 설명                                      | 우선순위 |
| -------------------- | ----------------------------------------- | -------- |
| 컨디션 점수 산출     | 날씨+미세먼지+자외선 통합 0～100 점수/등급 | **Must** |
| 점수 근거 표시       | 감점 요인 요약(예: 강수 -20)              | **Must** |
| 장비 추천            | 조건 기반 준비물 리스트                   | **Must** |
| 미세먼지/자외선 표시 | PM10/PM2.5, UV 지수                       | **Must** |
| 로그인/회원가입      | Supabase 인증                             | **Must** |
| 즐겨찾기 산          | 관심 산 저장/조회                         | Should   |
| 점수 시간대별 추이   | 오전/오후 점수 비교                       | Could    |

#### 화면 구성 (라우트 포함)

| 화면            | 라우트            | 구성 요소                                       |
| --------------- | ----------------- | ----------------------------------------------- |
| 검색 결과(확장) | `/mountains/[id]` | 컨디션 점수 게이지, 감점 근거, 장비 추천 리스트 |
| 로그인          | `/auth/login`     | (스타터 킷 재사용)                              |
| 회원가입        | `/auth/sign-up`   | (스타터 킷 재사용)                              |
| 즐겨찾기        | `/favorites`      | 저장한 산 카드 목록 (로그인 필요)               |

- 주요 컴포넌트: `ConditionScoreGauge`, `ScoreBreakdown`, `GearRecommendationList`, `AirUvSummary`(대기질·자외선 3칸 타일), `FavoriteButton`.

#### 컨디션 점수 알고리즘 (초안)

기준점 100점에서 감점 방식. **개발 시작점이며 실측 후 가중치 튜닝 필요.** 🔶

**입력 변수 및 가중치(감점 최대치)**

| 변수               | 출처       | 판단 기준(예시)           | 최대 감점 |
| ------------------ | ---------- | ------------------------- | --------- |
| 강수확률(POP)      | 기상청     | 30%↑ 감점 시작, 70%↑ 최대 | -25       |
| 강수형태(PTY)      | 기상청     | 비/눈/소나기 시 가산 감점 | -10       |
| 기온(TMP)          | 기상청     | 쾌적 5～22℃ 기준 이탈폭    | -20       |
| 풍속(WSD)          | 기상청     | 7m/s↑ 감점, 14m/s↑ 최대   | -15       |
| 미세먼지(PM10/2.5) | 대기 API   | '나쁨'부터 감점           | -20       |
| 자외선(UV)         | 자외선 API | '높음' 6↑부터 감점        | -10       |

> 감점 합계가 100을 넘으면 0으로 클램프. 각 변수 감점은 선형 보간 권장.

**점수 구간 → 등급**

| 점수   | 등급      | 메시지 예시                      |
| ------ | --------- | -------------------------------- |
| 80～100 | 매우 좋음 | "산행하기 완벽한 날!"            |
| 60～79  | 좋음      | "무난해요. 기본 장비 챙기세요."  |
| 40～59  | 보통      | "가능하지만 대비 필요."          |
| 20～39  | 나쁨      | "비추천. 꼭 간다면 철저히 대비." |
| 0～19   | 위험      | "산행 자제 권장."                |

**장비 추천 규칙 (예시)**

| 조건                         | 추천 장비                      |
| ---------------------------- | ------------------------------ |
| POP ≥ 50% 또는 PTY=비/소나기 | 방수 자켓, 배낭 레인커버       |
| TMP ≤ 5℃                     | 방한 장갑, 넥워머, 보온 레이어 |
| TMP ≥ 28℃                    | 여벌 물, 전해질, 모자          |
| UV ≥ 6                       | 선크림, 선글라스, 챙모자       |
| WSD ≥ 10m/s                  | 바람막이, 체온 유지 레이어     |
| PM10/2.5 '나쁨'↑             | KF 마스크                      |

#### 데이터 요구사항

- **Supabase 테이블:** `profiles`(선택), `favorites`, `condition_scores`(캐시, 선택).
- **외부 API 추가:** 미세먼지(PM10/PM2.5), 자외선 지수.
- 점수 계산은 서버(Route Handler 또는 서버 유틸)에서 수행, 계산 로직 버전 태깅. 🔶

#### 완료 기준 (Acceptance Criteria)

- [ ] 결과 화면에 0～100 점수와 등급/메시지가 표시된다.
- [ ] 주요 감점 요인 2～3개가 근거로 노출된다.
- [ ] 조건에 맞는 장비 추천 리스트가 노출된다.
- [ ] 로그인 사용자가 산을 즐겨찾기에 추가/삭제할 수 있다.
- [ ] `favorites`는 RLS로 본인 데이터만 접근 가능하다.
- [ ] 미세먼지/자외선 API 실패 시 해당 변수를 제외하고 점수를 계산(부분 폴백)한다.

### 4.3 3단계 — 지도 + PWA

#### 사용자 스토리

- (누가) 등산객이 (무엇을) 지도 위 등산로와 홈 화면 앱을 (왜) 코스를 시각적으로 파악하고 앱처럼 빠르게 재접속하기 위해.

#### 핵심 기능 목록 (우선순위)

| 기능                  | 설명                   | 우선순위 |
| --------------------- | ---------------------- | -------- |
| 카카오맵 표시         | 산 위치 지도 렌더링    | **Must** |
| 등산로 오버레이       | 폴리라인으로 코스 표시 | **Must** |
| 탐방로 상태 지도 연동 | 통제 구간 색상 구분    | Should   |
| PWA 설치              | manifest + 서비스워커  | **Must** |
| 홈 화면 추가 유도     | 설치 배너/안내         | Should   |
| 오프라인 폴백         | 마지막 조회 캐시 표시  | Could    |

#### 화면 구성 (라우트 포함)

| 화면               | 라우트                | 구성 요소                             |
| ------------------ | --------------------- | ------------------------------------- |
| 산 상세(지도 확장) | `/mountains/[id]`     | 지도 섹션, 등산로 오버레이, 상태 범례 |
| 지도 전체보기      | `/mountains/[id]/map` | 전체화면 지도                         |
| 오프라인           | `/offline`            | 네트워크 단절 안내                    |

- 주요 컴포넌트: `KakaoMap`, `TrailOverlay`, `MapLegend`, `PwaInstallPrompt`.

#### 데이터 요구사항

- **Supabase 테이블:** `trails`에 `path_geojson`(코스 좌표) 컬럼 추가.
- 카카오맵 SDK 로드는 클라이언트 컴포넌트 + 스크립트 지연 로딩.
- `manifest.json`, 아이콘 세트, 서비스워커(캐싱 전략) 필요. 🔶

#### 완료 기준 (Acceptance Criteria)

- [ ] 산 상세에서 카카오맵과 등산로 폴리라인이 표시된다.
- [ ] 통제 구간이 색상으로 구분된다(데이터 있는 경우).

## 6. 외부 API 연동 명세

### 6.1 기상청 단기예보 (1단계)

- **용도:** 오늘 날씨(기온·강수확률·하늘상태·강수형태·풍속).
- **핵심 응답 필드:** `TMP`, `POP`, `PTY`, `SKY`, `WSD`, `REH`(습도), `TMN`/`TMX`(일 최저/최고, Task 034).
- **입력:** 격자 좌표(nx, ny), base_date/base_time.
- **후보:** 기상청 공공데이터포털 단기예보 조회서비스. 🔶(초단기 vs 단기 선택 필요)
- **확장 활용(Task 034):** 동일 응답 하나에서 **시간대별·3일 요약 예보·오늘 최저/최고**를 함께 파싱한다(추가 호출 없음). **체감온도**는 기온·습도·풍속으로 산출(외부 API 불필요), **일출·일몰**은 산 위경도로 계산한다(외부 API 불필요).

### 6.2 탐방로 개방정보 (1단계)

- **용도:** 탐방로 개방/통제 상태.
- **핵심 응답 필드:** 산명, 탐방로명, 개방상태, 통제사유, 통제기간.
- **후보:** 국립공원공단 탐방로 개방정보. 🔶(국립공원 외 산 커버리지 한계 → 대체/보완 소스 필요)

### 6.3 미세먼지 (2단계)

- **용도:** PM10/PM2.5 등급.
- **핵심 응답 필드:** `pm10Value`, `pm25Value`, `pm10Grade`, `pm25Grade`.
- **후보:** 한국환경공단 에어코리아 대기오염정보. 🔶(측정소 매핑: 산 인근 측정소 선정 규칙 필요)

### 6.4 자외선 지수 (2단계)

- **용도:** UV 지수.
- **핵심 응답 필드:** `uvIndex`/시간대별 값.
- **후보:** 기상청 생활기상지수(자외선). 🔶

### 6.5 카카오맵 SDK (3단계)

- **용도:** 지도 렌더링, 등산로 폴리라인.
- **주의:** JS 키 도메인 등록, 클라이언트 로드, CSP/스크립트 정책.

### 공통 연동 원칙

- 모든 외부 호출은 **서버(Route Handler/서버 유틸)에서 프록시** → API 키 노출 방지, 캐싱 일원화.
- 응답은 앱 내부 표준 스키마로 정규화 후 컴포넌트 전달.
- **캐싱/갱신 주기 🔶:** 날씨 10～30분, 대기질 1시간, 탐방로 상태 1～6시간 (초안). `next.config.ts`의 `cacheComponents: true` 및 `"use cache"` 활용 검토.

## 7. 비기능 요구사항

### 성능 (모바일 우선)

- 결과 페이지 LCP 4G 기준 2.5s 이하(1단계) → 2.0s 이하(3단계).
- 외부 API는 서버 캐싱으로 반복 호출 최소화.
- 지도/무거운 스크립트는 지연 로딩(3단계).

### 접근성

- 색상만으로 상태 구분 금지(개방/통제는 아이콘+텍스트 병행).
- 터치 타깃 최소 44x44px, 폼 라벨/aria 속성 준수.
- 컨디션 점수 게이지는 텍스트 등급/메시지 병기.

### 에러/로딩 상태 처리

- 모든 데이터 페칭 구간에 스켈레톤/로딩 표시.
- 에러는 사용자 친화 메시지 + 재시도 버튼.
- 부분 실패 허용: 일부 데이터 소스 실패 시 가능한 정보만 표시.

### 외부 API 실패 시 폴백 전략

- **날씨 실패:** "날씨 정보를 불러오지 못했습니다" + 재시도. 탐방로 정보만이라도 표시.
- **탐방로 실패:** 상태를 "정보 없음"으로 표기, 날씨는 정상 표시.
- **대기질/자외선 실패(2단계):** 해당 변수를 점수 계산에서 제외하고 점수에 "일부 데이터 제외" 표기.
- **지도 실패(3단계):** 정적 좌표/외부 지도 링크 폴백.
- 최근 성공 응답 캐시가 있으면 "N분 전 기준" 라벨과 함께 노출.

### 보안/세션

- `@supabase/ssr` 쿠키 기반 세션, 세션 확인은 `getClaims()` 관례 사용.
- 즐겨찾기 등 개인 데이터는 RLS 강제.
- 외부 API 키는 서버 환경변수로만 관리.

### 10.1 상세 화면 확장 (신규 데이터 소스 필요)

산 상세 화면을 더 풍부하게 만드는 확장 항목이다. **이미 연동된 소스(기상·대기·자외선·탐방로)로 가능한 확장**(체감온도·시간별/3일 예보·미세먼지·자외선 실수치·일출/일몰·코스 요약)은 3단계 이후 순차 반영되었고(ROADMAP Task 034), 아래 항목은 **신규 외부 데이터 소스 확보가 선행되어야** 하므로 별도 개발 단계로 계획한다.

| 항목                    | 내용                                                          | 필요 데이터 소스                    |
| ----------------------- | ----------------------------------------------------------- | ----------------------------------- |
| 실시간 통제·공지        | 국립공원 실시간 입산 통제·안전 공지(정적 CSV가 아닌 실시간)  | 국립공원공단 실시간 API/공지        |
| 산불위험지수·입산통제   | 산불 위험 등급, 산불 조심 기간 입산 통제 현황               | 산림청 산불위험예보                 |
| 주차·교통·입장료        | 주차장 위치·혼잡도, 대중교통 접근, 입장/주차 요금           | 지자체·공영주차장·대중교통 API      |
| 편의시설                | 화장실·대피소·식수대·매점 위치                              | 국립공원 시설 데이터·지도 POI       |
| 전망 사진·포토스팟      | 정상·주요 지점 전망 사진, 추천 포토스팟                     | 이미지 저장소·큐레이션              |
| 사용자 후기·별점        | 방문자 리뷰, 코스별 별점·난이도 체감                        | 자체 리뷰 DB(신규 스키마·인증 연계) |
| 계절 명소·야생동물 주의 | 단풍·설경 등 시즌 정보, 곰·멧돼지 등 야생동물 출몰 주의     | 국립공원 계절 콘텐츠·안전 공지      |

> 후기·사진·실시간 통제 등은 [8장 범위 밖](#8-범위-밖-out-of-scope)에서 초기 제외로 명시했던 항목이다. 상세 화면 고도화 수요가 확인되면 데이터 소스 확보를 전제로 스코프에 편입한다.
